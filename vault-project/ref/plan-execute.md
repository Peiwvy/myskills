# plan + execute

plan 和 execute 发生在 `inprogress-*.md` 内部。不再有独立的 `plan.md`。

---

## plan（在 inprogress 内制定方案）

何时需要详细拆分：
- 多步骤，步骤间有依赖
- 需要子 agent 并行
- 需要明确验证标准
- 跨 session 的长任务

简单任务在 inprogress 写清楚目标和检验即可，不需要详细拆分。

### inprogress 内的 plan 段

```markdown
# inprogress-A

- 来源：INBOX 梳理区 #A
- 目标：一句话
- 计划：
  - 步骤1：... [→ 自己做 / agent <类型>]
  - 步骤2：... [依赖：步骤1]
  - 步骤3：... [依赖：步骤1]
- 问题：...
- 决策：...
- 检验：怎么验证做对了
```

### 关键

- **每个步骤写清楚谁做**（自己做 / 派什么类型的 agent）
- **检验要具体**：不说「确保质量」，说「跑测试全部通过」
- **依赖明确**：子 agent 拿到自己的步骤 + 检验就能独立工作

---

## execute（执行 inprogress）

触发：「开始执行」「继续」。

### 步骤

1. 读 `inprogress-*.md`，确认当前状态
2. 对计划中每个待执行步骤：
   - 按派发判据决定自己做 or 派子 agent
   - 子 agent 拿到：**步骤描述 + 检验方法 + 相关上下文**
3. 子 agent 完成后：
   - 对照检验方法验证
   - 不通过 → 说明哪里不对，让它重来
   - 通过 → 更新 inprogress（进度 + 决策）
4. 全部步骤完成 → 触发 **complete** 流程

### 派发判据

| 情况 | 做法 |
|------|------|
| 单一步骤，上下文够 | 自己做 |
| 独立子任务，不需共享状态 | 派子 agent 并行 |
| 需要和外部系统交互（代码仓等） | 派子 agent，给清路径和命令 |
| 需要判断/审查 | 自己做（coordinator 负责判断） |

### 防腐败

- 派子 agent 时**只给相关上下文**，不 dump 整个 CLAUDE.md
- 子 agent 任务描述自包含
- inprogress 是共享上下文：子 agent 可读全局计划，只改自己负责的部分
- 遇到架构冲突 → 暂停，回来问 coordinator

---

## complete（收尾）

全部步骤完成后：

1. 问：「是否需要把结论写入内容文件？」
2. 是 → 更新对应内容文件（架构说明 / 设计文档 / 等）
3. 更新 CLAUDE.md 路由（如果内容结构变了）
4. 从 `_cockpit/INBOX.md` 梳理区删除对应条目
5. 删除 `inprogress-*.md`
